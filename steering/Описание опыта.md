# Опыт steering: перенос значения между аргументами инструмента

Предыдущая версия опыта (steering v1) лежит в истории git, коммит `steering v1`. Здесь описана текущая версия (v2).

## 1. Чем v2 отличается от v1

Ниже отличия в авторской формулировке, слегка уточнённой.

**Вопрос.** В v1 проверялось, что порядок аргументов в вызове не влияет на стиринг. Это установлено, и теперь порядок не рассматривается.
В v2 смотрим, **как успех стиринга зависит от номера аргумента и от семантики его значения**: например, получится ли записать
в слот имени пункт назначения.

**Что изменено.**

- **Инструменты.** Новый набор из пяти инструментов, в каждом по **пять аргументов**. Аргументы абсолютно разные по семантике, в том числе
  внутри одного инструмента (имя, цвет, город, животное, месяц и т. д.). Значения однотокенные. Инструментов немного.
- **Переходы.** Стиринг делается между аргументами по номеру: **1→3, 3→5, 5→3, 3→1**. Переход o→d означает, что в слот аргумента o
  мы пытаемся заставить модель записать значение аргумента d.
- **Векторы.** Для каждого инструмента строится свой вектор каждого перехода, `steer_tool_{o}_{d}`: он двигает значение o→d.
  Добавлен «неродный» вектор того же перехода, посчитанный по остальным инструментам, `steer_foreign_{o}_{d}`.
- **Убрано.** Векторы `steer_same`, `steer_opp`, `steer_layout`, а вместе с ними идея варианта вызова со временем (положение даты
  в вызове) и порядка ключей. Из-за этого же не нужны `steer_pos`, `steer` (общий вектор по рейсам) и `steer_dom` (вектор типа задач):
  они опирались на порядок, вариант вызова или деление на типы задач.
- **Оставлено.** Контрольные векторы: `steer_neg`, `shuffled`, `random0`, `random1`, а также подмена активации `patch`.
- **Слои.** Окно расширено на 10 слоёв вправо и на 5 влево: вместо 18–27 теперь **13–37**.
- **Графики.** Кроме успеха своего вектора, показывается успех векторов переходов 3→5 и 5→3, взятых у неродных инструментов, для каждого инструмента.

| | v1 | v2 |
|---|---|---|
| Инструменты | 44: 6 пар ключей рейсов в двух порядках и трёх вариантах вызова, письма, периоды | 5 инструментов по 5 аргументов |
| Слоты | 2 (origin, destination), порядок od/do | 5 аргументов, переходы 1→3, 3→5, 5→3, 3→1 |
| Что варьируется | порядок ключей, положение даты, тип задач | номер аргумента и семантика значения |
| Свои векторы | `steer`, `steer_same`, `steer_opp`, `steer_layout`, `steer_pos`, `steer_dom`, `steer_tool` | `steer_tool_{o}_{d}`, `steer_foreign_{o}_{d}` |
| Контроли | `steer_neg`, `shuffled`, `random0`, `random1`, `patch` | те же |
| Слои | 18–27 | 13–37 |
| Третье значение X в промпте | есть, отвлекатель | нет: роль «чужих» значений играют три остальных аргумента (R) |

## 2. Обозначения

- $l$ — слой; $h^{(l)}_p \in \mathbb{R}^d$ — вход блока $l$ (`blocks.l.hook_resid_pre`) в позиции $p$.
- Аргументы нумеруются $k = 1,\dots,5$ в порядке вызова. Значение аргумента $k$ в примере — $x_k$.
- Переход $(o, d)$, $o \ne d$: из набора $\{(1,3), (3,5), (5,3), (3,1)\}$. Слоты, чьи состояния нужны для векторов: $\{1, 3, 5\}$.
- Для примера и перехода $(o,d)$: свой $S = x_o$, целевой $T = x_d$, остальные три значения $R = \{x_k : k \ne o, d\}$.

## 3. Данные

### 3.1. Инструменты

У каждого инструмента пять аргументов разных семантических типов; на позициях 1, 3, 5 разных инструментов стоят 15 разных типов.

| Инструмент | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| `book_trip` | passenger (имя) | bag_color (цвет) | destination (город) | pet (животное) | month (месяц или день недели) |
| `submit_form` | injury (часть тела) | garden_plant (растение) | lunch (еда) | transport (транспорт) | language (язык) |
| `register_item` | venue (здание) | furniture (мебель) | tool (инструмент) | material (материал) | origin_country (страна) |
| `log_record` | outfit (одежда) | ride (транспорт) | topic (школьный предмет) | badge_color (цвет) | symbol (форма) |
| `create_entry` | paint (цвет) | seat (мебель) | mascot (животное) | tree (растение) | medium (материал) |

Пример из задачи: в `book_trip` слот 1 — имя пассажира, слот 3 — город назначения. Переход 1→3 заставляет модель записать
в слот имени город назначения, а 3→1 — имя в слот города.

### 3.2. Значения и шаблоны

- **Пулы значений.** Для каждого типа берутся только однотокенные значения; токены не повторяются ни внутри типа, ни между типами,
  поэтому пять значений одного вызова всегда различны. Половина значений типа идёт в калибровку (`calib`), половина в тест (`test`), без пересечений.
- **Сообщение пользователя.** Просьба инструмента и пять пар «подпись: значение» (например, `Passenger: Alice`).
  Четыре шаблона: `kv_fwd`, `kv_rev` (по строкам) и `inline_fwd`, `inline_rev` (в одну строку); `fwd` перечисляет аргументы в порядке 1..5, `rev` — 5..1.
  Для калибровки используются `kv_*`, для теста все четыре.
- **Промпт.** Чат-шаблон модели со схемой инструмента (все пять параметров обязательные), режим размышления отключён.
- **Вызов.** `<function name="…"><param name="k1">v1</param><param name="k2">v2</param>…`.

## 4. Как строятся векторы

### 4.1. Состояния слотов

Для примера $(x_1,\dots,x_5)$ инструмента $\tau$ прогоняется полный вызов с **teacher forcing** (все значения подставляются верные).
Позиция слота $k$ — токен непосредственно перед первым токеном значения $x_k$ (в этой разметке это `">`):

$$p_k = (\text{индекс первого токена } x_k) - 1, \qquad h^{(l)}_k = h^{(l)}_{p_k}.$$

Состояния читаются хуками на `hook_resid_pre`, которые записывают активации слоёв в заранее выделенный тензор.

### 4.2. Калибровка и фильтр

Для каждого инструмента берётся `N_PER_TOOL = 120` примеров: значения из пулов `calib`, шаблоны по кругу из `kv_fwd`, `kv_rev`.
Пример остаётся, если модель сама верна **во всех трёх слотах** $k \in \{1,3,5\}$:

$$\arg\max \text{logits}(p_k) = \mathrm{tok}_1(x_k), \qquad k = 1, 3, 5.$$

Остаётся $n_\tau \le 120$ примеров $i = 1,\dots,n_\tau$ на инструмент.

### 4.3. Свой вектор перехода

$$v_\tau^{o \to d,(l)} = \frac{1}{n_\tau}\sum_{i} h^{(l)}_{d,i} - \frac{1}{n_\tau}\sum_{i} h^{(l)}_{o,i}.$$

Так как для всех переходов используются одни и те же примеры инструмента, обратный переход даёт тот же вектор с минусом:
$v_\tau^{5\to 3} = -v_\tau^{3\to 5}$ и $v_\tau^{3\to 1} = -v_\tau^{1\to 3}$. Проверять переходы всё равно нужно отдельно, потому что вектор добавляется
в разные слоты: 3→5 добавляется в слот 3, а 5→3 — в слот 5.

### 4.4. Неродной вектор

Тот же переход, посчитанный по примерам **всех остальных** инструментов, без целевого $\tau$ (leave-one-out); примеры объединяются, а не усредняются средние:

$$\tilde v_\tau^{o \to d,(l)} = \frac{1}{N_{-\tau}}\sum_{\tau' \ne \tau}\sum_{i} h^{(l)}_{d,i} - \frac{1}{N_{-\tau}}\sum_{\tau' \ne \tau}\sum_{i} h^{(l)}_{o,i}, \qquad N_{-\tau} = \sum_{\tau' \ne \tau} n_{\tau'}.$$

У остальных инструментов на позициях $o$ и $d$ стоят другие по смыслу аргументы, поэтому разница между своим и неродным вектором показывает, насколько вектор перехода зависит от семантики.

### 4.5. Нормировка

Все векторы условий приводятся к норме **своего** вектора перехода на каждом слое:

$$\mathrm{u}(w)^{(l)} = \lVert v_\tau^{o \to d,(l)} \rVert \cdot \frac{w^{(l)}}{\lVert w^{(l)} \rVert}.$$

Так условия различаются только направлением, а сила $\alpha$ одинакова.

### 4.6. Условия

Для инструмента $\tau$ и перехода $(o,d)$:

| Условие | Вектор | Смысл |
|---|---|---|
| `steer_tool_{o}_{d}` | $v_\tau^{o \to d}$ | свой вектор перехода |
| `steer_foreign_{o}_{d}` | $\mathrm{u}(\tilde v_\tau^{o \to d})$ | тот же переход по остальным инструментам |
| `steer_neg` | $-v_\tau^{o \to d}$ | контроль: обратное направление |
| `shuffled` | $\mathrm{u}(d_{\mathrm{shuf}})$ | контроль: перемешанные метки, см. ниже |
| `random0`, `random1` | $\mathrm{u}(\xi_k)$, $\xi_k \sim \mathcal{N}(0, I)$, seed $k \in \{0,1\}$ | контроль: случайное направление |

**Контроль `shuffled`.** Для каждого инструмента выбирается одна случайная маска $m_i \in \{0,1\}$ ровно с $\lfloor n_\tau/2 \rfloor$ единицами, и у этих
примеров метки слотов $o$ и $d$ меняются местами:

$$\tilde D = \frac{1}{n_\tau}\sum_i \big(m_i h_{o,i} + (1 - m_i) h_{d,i}\big) - \frac{1}{n_\tau}\sum_i \big(m_i h_{d,i} + (1 - m_i) h_{o,i}\big).$$

Затем убирается проекция на свой вектор, чтобы контроль не содержал роль:

$$d_{\mathrm{shuf}} = \tilde D - \langle \tilde D, \hat v \rangle\,\hat v, \qquad \hat v = v_\tau^{o\to d} / \lVert v_\tau^{o\to d} \rVert.$$

> Слой 0 исключён из смысла: `resid_pre` слоя 0 — это эмбеддинг токена, а перед значением любого слота стоит один и тот же токен,
> поэтому $v^{(0)} = 0$ и нормировка там даёт NaN. Стиринг идёт только по слоям `LAYER_RANGE`, поэтому на результат это не влияет.

## 5. Как проводится вмешательство

Для тестового примера (значения из пулов `test`, один из четырёх шаблонов, переход $(o, d)$):

1. **Контекст.** Строится вызов до значения аргумента $o$ с верными значениями аргументов $1,\dots,o-1$ (teacher forcing). Слот $o$ — последняя позиция.
2. **Добавка.** На слое $l$ к последней позиции прибавляется вектор условия:
   $$h^{(l)}_{\mathrm{last}} \leftarrow h^{(l)}_{\mathrm{last}} + \alpha\, w^{(l)}.$$
   Знак всегда плюс: переход $o \to d$ уже заложен в направлении вектора. Вмешательство идёт на **одном слое за раз**, слои из `LAYER_RANGE`,
   силы $\alpha$ из `ALPHAS` (для контролей `CTRL_ALPHAS`). Логиты читаются в последней позиции.
3. **Patch.** Для сравнения на каждом слое подставляется активация последней позиции из прогона того же контекста с переставленными
   значениями аргументов $o$ и $d$ ($x_o \leftrightarrow x_d$) во всём промпте и предыдущем вызове. Это верхняя оценка того, что даёт правка одной позиции.

Метрики для каждой строки `raw.csv`:

$$\Delta = z_T - z_S, \qquad \Delta_{\mathrm{base}}\ \text{— то же без вмешательства}, \qquad \mathrm{shift} = \Delta - \Delta_{\mathrm{base}},$$

$$p_T = \Pr[\arg\max = T], \quad p_S, \quad p_R = \Pr[\arg\max \in R], \quad p_{\mathrm{other}} = 1 - p_T - p_S - p_R,$$

где $z$ — логиты последней позиции. Главная метрика — **доля целевого значения** $p_T$.

## 6. Какие примеры идут в анализ

Остаются примеры, где без вмешательства выполнено оба условия:

- **`base_ok`:** модель сама выдаёт $S$ в слоте $o$;
- **`ctx_ok`:** модель сама верно пишет значения всех предыдущих аргументов $1,\dots,o-1$ (для $o = 1$ условие выполнено всегда).

Иначе нельзя отделить эффект вектора от исходной ошибки модели.

## 7. Статистика

- Доля $p_T$ при $L_0 = 23$, $A_0 = 3.0$ по ячейкам (инструмент, переход, вид условия) и по всем инструментам сразу, с 95% доверительным интервалом Уилсона.
- **Разрыв** $\mathrm{gap} = p_T(\texttt{steer\_tool}) - p_T(\texttt{steer\_foreign})$ по ячейкам (`gap_*.csv`).
  Малый разрыв говорит о том, что вектор перехода мало зависит от семантики, а большой — что он привязан к ней.
- **Парные сравнения (McNemar, точный).** Пары — один и тот же пример $(\text{инструмент},\ \text{шаблон},\ \text{значения})$ под двумя видами условий $A$ и $B$.
  Пусть $b$ — число примеров, где цель достигнута только под $A$, $c$ — только под $B$:
  $$p\text{-value} = \text{биномиальный тест}\ \big(b;\ b + c,\ 0.5\big).$$
  Сравнения: `steer_tool` и `steer_foreign`, `steer_tool` и `shuffled`, `steer_foreign` и `shuffled`, `steer_tool` и `steer_neg` по каждому переходу
  (по всем инструментам), а первые два дополнительно по каждому инструменту. Поправка на множественные сравнения **не** вводится.
- «Куда уходит выдача»: доли $p_T, p_S, p_R, p_{\mathrm{other}}$ для `steer_tool` и `steer_foreign`.

## 8. Что ожидается

Ожидания следуют из дизайна, а не из результатов; их нужно сверить с автором опыта.

| Ожидание | Что его подтвердит | Что опровергнет |
|---|---|---|
| Вектор перехода работает на своём инструменте | $p_T(\texttt{steer\_tool})$ заметно выше, чем у `random`, `shuffled` и `steer_neg` на части слоёв | $p_T(\texttt{steer\_tool})$ не отличается от случайных направлений |
| Контроли ведут себя как контроли | `shuffled` близок к `random`, `steer_neg` не повышает $p_T$ | `shuffled` работает не хуже `steer_tool` |
| Семантика значения влияет на успех | разрыв gap заметно больше нуля, $p_T(\texttt{steer\_foreign})$ заметно ниже | $p_T(\texttt{steer\_foreign})$ близок к $p_T(\texttt{steer\_tool})$: вектор перехода от семантики не зависит |
| Номер аргумента влияет на успех | $p_T$ различается между переходами 1→3, 3→5, 5→3, 3→1 | $p_T$ по переходам одинаков |
| Эффект зависит от слоя | $p_T$ меняется по слоям 13–37, есть выраженный максимум | плоская кривая |
| Patch — верхняя оценка | $p_T(\texttt{patch})$ не ниже $p_T(\texttt{steer\_tool})$ на соответствующем слое | $p_T(\texttt{patch})$ ниже: правки одной позиции мало |

Запуск из папки `steering`:

```bash
python main.py --test     # быстрая проверка, результаты в results/test
python main.py --run      # полный прогон, результаты в results/run_<время>
```

Опции: `--model` (имя на HF или локальная папка), `--device` (`auto`, `cuda`, `cpu`), `--out` (своя папка результатов).
